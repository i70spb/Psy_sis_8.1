## Правила работы

### 1. Один узел — один файл
Каждая сущность (ловушка, метод, протокол, кейс) — отдельная карточка в своём файле. Добавление нового узла требует правки только одного файла.

### 2. Связи через теги
Связи между сущностями создаются через теги внутри карточки. Никаких глобальных разделов «Связи» в конце файлов.

### 3. Вход через тег
Любая тема открывается через поиск по тегу. Тег даёт контекст и связи.

### 4. Запись по шаблону
Новая запись начинается с шаблона (см. `09_TEMPLATES.md`).

### 5. Приоритет реальности
Любое правило пересматривается, если реальность его опровергает.

## Теги и правила

Все теги формируются по правилу в`08_TAGS.md`. Формат: `#префикс_название` (нижний регистр, без пробелов).

**Префиксы:**
- `#аксиома_` — базовые законы
- `#переменная_` — измеряемые параметры
- `#механика_` — процессы
- `#эмоция_` — эмоции
- `#ловушка_` — типовые ошибки прогноза
- `#метод_` — инструменты
- `#протокол_` — алгоритмы
- `#кейс_` — примеры
- `#детское_правило_` — источники ловушек

## Быстрый чек-лист

1. Найди тег, ближе всего к твоей теме.
2. Открой соответствующий файл.
3. Прочитай карточку сущности.
4. Если нужно — добавь свой кейс по шаблону.
5. Свяжи его тегами с существующими узлами.

## Архитектурный принцип
